## 1. Цель

Получение данных асинхронно с помощью `Promise`, `async/await`, `fetch` и `Promise.all`, работа с JSON, URLSearchParams, статусами HTTP, отменой запросов, ограничением времени и валидацией ответа.

## 2. Структура и назначение модулей

- `api/data.js` — исходные 12 задач и 3 категории.
- `api/server.mjs` — готовая учебная серверная часть (данные только для чтения).
- `src/api-client.js` — общий транспортный клиент: URL, GET, заголовки, статус, JSON, тайм-аут, типизированные ошибки.
- `src/task-api.js` — предметный API для задач, категорий, схемы данных и параллельной начальной загрузки.
- `src/variant.js` — номер варианта и фильтры.
- `src/main.js` — контрольный консольный сценарий.
- `examples/event-loop.js`, `examples/fetch-basics.js`, `examples/delay-compare.js` — наблюдения за асинхронностью, HTTP и Promise.all.
- `checks/` — автоматические проверки без сторонних npm-пакетов.

## 3. Окружение и запуск

Заданием рекомендуется **Node.js 24 LTS**; код дополнительно проверен в окружении Node.js **v22.16.0**, npm **10.9.2**. На компьютере автора версии нужно указать по факту:

```bash
node --version
npm --version
git --version
```

В WebStorm открыть проект `tip-js-practices`, перейти в `practice-05`. В терминале №1:

```bash
cd practice-05
npm start
```

Адрес API — `http://127.0.0.1:5505/api`; открыть `http://127.0.0.1:5505/api/health`. В терминале №2 **в папке practice-05**:

```bash
npm run example:order
npm run example:fetch
npm run client
```

Не нужно выполнять `npm install`. Остановить сервер: `Ctrl+C`. При занятом 5505 можно запустить `node api/server.mjs 5515`, а клиент командой `API_URL=http://127.0.0.1:5515/api npm run client` (macOS/Linux).

## 4. Асинхронная модель — прогноз и фактический результат

**Прогноз:** синхронные A, B, C, затем две исходные микрозадачи D, E, добавленная собственная микрозадача G, затем таймер F.

**Результат запуска `npm run example:order`:** `A → B → C → D → E → G → F`.

A, B, C выполняются в текущем стеке; продолжения Promise и `await` размещаются в очереди микрозадач. Затем выполняется задача таймера `setTimeout(..., 0)`.

## 5. Наблюдения HTTP

| Запрос | Статус | `ok` | `Content-Type` | Тело |
|---|---:|---|---|---|
| `/api/health` | 200 | true | application/json | `{data:{status:"ok"}}` |
| `/api/tasks` | 200 | true | application/json | массив 12 задач и `meta` |
| `/api/tasks?completed=false&priority=high` | 200 | true | application/json | ID `[4,13,34]` |
| `/api/tasks/25` | 200 | true | application/json | одна задача |
| `/api/tasks/999` | 404 | false | application/json | `TASK_NOT_FOUND` |
| `/api/categories` | 200 | true | application/json | 3 категории и `meta` |

Проверка `response.ok` выполняется явно: `fetch` не превращает статус 404 в rejected Promise. Статус `204` интерпретируется как `null` без попытки прочитать JSON.

## 6. Виды ошибок

| `ApiError.kind` | Причина | Действия |
|---|---|---|
| `http` | Получен HTTP-ответ с кодом 4xx/5xx | Сохранить `status`, `code`, `details`, `url` |
| `network` | Ответ не получен | Сохранить `cause`, `url` |
| `invalid-response` | Нет JSON или схема неверна | Отклонить данные, не передавать их приложению |
| `timeout` | Сработал `AbortSignal.timeout` | Показать превышение времени |
| `aborted` | Запрос отменил вызывающий код | Не путать с ошибкой сети |

`buildUrl` не теряет `false` и `0`, пропускает `null`, `undefined`, `""`, не меняет исходный `query`.

## 7. Последовательное и параллельное ожидание

Команда `API_URL=http://127.0.0.1:5505/api node examples/delay-compare.js` делает по три измерения с задержкой сервера 150 мс на запрос.

Фактические результаты одного локального прогона:

| Способ | 1 | 2 | 3 |
|---|---:|---:|---:|
| Последовательно, мс | 364 | 306 | 312 |
| `Promise.all`, мс | 153 | 157 | 159 |

`Promise.all` позволяет двум независимым запросам выполняться одновременно. Время зависит от компьютера.

## 8. Контрольный и индивидуальный сценарии

Для общего контрольного запроса `{completed:false,priority:'high'}` ожидаемые ID `[4,13,34]`. Индивидуальный вариант 6 использует `{categoryId:2}` — ID `[4,16,22,25,28,34]`, `meta.total=6`. Сформированный URL:

`http://127.0.0.1:5505/api/tasks?categoryId=2`

Контрольный результат `npm run client`: 6 задач категории «Проект»; запрос задачи №999 отдельно классифицируется как `http`, статус 404, код `TASK_NOT_FOUND`.

Номер варианта фиксирован: 6. Менять код под другой вариант для данной работы не требуется.

## 9. Автоматизированные проверки

Результат фактического прогона **поставляемых вместе с этим решением** проверок:

```text
Итог API: успешно 18, ошибок 0.
Итог клиента: успешно 26, ошибок 0.
Итог интеграции: успешно 13, ошибок 0.
```

**Три собственные проверки:** сочетание фильтров `completed=false&priority=high&categoryId=2`, неверный `Content-Type` при 502 (приоритет статуса) и тайм-аут с задержкой 200 мс при лимите 20 мс. Дополнительно проверены 204, неверная схема, отмена, уникальность ID, пробелы и кириллица в URL.

Реализован переиспользуемый асинхронный HTTP-клиент с пятью видами ошибок и предметный клиент задач. Проверена параллельная загрузка данных, тайм-аут, внешняя отмена, работа с запросами и схемами данных. Клиент не требует браузера и может быть использован в следующей практической работе.
